# Какой форк дорабатывать: Wealthfolio или ignidash

Дата: 2026-09-24. Wealthfolio — `main` @ `5ef41f1` и релизы v3.6.3 → v3.7.0 → v3.8.0; ignidash — `main` @ `a0d4f3a`.
Вопрос: что выгоднее дорабатывать в своём форке. Исходные разборы: [ignidash-fork-plan.md](ignidash-fork-plan.md),
[wealthfolio-plan.md](wealthfolio-plan.md).

## Коротко

**Wealthfolio**, но при одном условии: наш код живёт в основном вне форка, в аддоне, а сам форк — это
несколько небольших правок. Цену форка определяет не выбор проекта, а то, сколько нашего кода лежит
в файлах, которые upstream часто меняет.

- **ignidash** проще менять «в лоб»: upstream остановился, конфликтов не будет, язык один, продукт уже
  планировщик. Но все 73 тыс. строк становятся нашими навсегда — вместе с американской логикой в 95 файлах,
  Convex, авторизацией и обновлениями безопасности 44 зависимостей. Учёт портфеля и Progress пришлось бы
  писать с нуля.
- **Wealthfolio** — движущаяся цель: 14 релизов за полгода, каждый минорный релиз меняет 450–520 файлов
  кода. Глубокий форк там утонет в конфликтах при обновлениях. Тонкий форк обходится дёшево: места, которые мы правим,
  меняются между релизами на десятки–сотни строк, а весь планировщик сидит в аддоне за SDK.

Текущий план (аддон + тонкий форк) этим подтверждается; в фазу 0 добавлены две проверки — см. конец.

## Сравнение по критериям

| Критерий | ignidash | Wealthfolio | Лучше |
|---|---|---|---|
| Upstream после форка | Остановился 16.03.2026: конфликтов нет, но нет и исправлений | 14 релизов за 6 месяцев; минорный релиз — 450–520 файлов кода, +21–44 тыс. строк | Зависит от глубины форка — см. следующий раздел |
| Куда класть наш код | Только внутрь: механизма расширений нет | В аддон через SDK или в свою папку; в самом форке — точки подключения | Wealthfolio |
| Что уже есть для цели | Половина «план»: планы, доходы и расходы, долги, недвижимость, взносы, Monte Carlo, бэктест — всё под США | Половина «учёт»: счета, лоты FIFO, недвижимость и долги, история по дням; планировщик простой | Ничья |
| Что придётся вырезать | Американскую логику из 95 файлов; Stripe, PostHog, AI, авторизацию | Ничего | Wealthfolio |
| Объём и языки | 73 тыс. строк, только TypeScript | 308 тыс. строк Rust + 269 тыс. TS; тонкий форк трогает малую часть | ignidash — если форк глубокий |
| Тесты и дисциплина | 1 221 unit-тест, 3 e2e-сценария; в CI — тесты | 3 624 теста на Rust, 2 169 на TS, несколько наборов Playwright (в том числе для песочницы аддонов); в CI clippy без предупреждений и проверка согласованности адаптеров; `AGENTS.md` с правилами | Wealthfolio |
| Сборка на Windows | Node + локальный Convex + Next.js, без Rust | Node 24 + pnpm + Rust (940 пакетов) + Tauri + VS Build Tools; холодная сборка долгая; в upstream есть готовый workflow сборки под Windows. У вас уже стоит Node 24; Rust и pnpm нужно поставить | ignidash |
| Данные и приватность | Convex + вход в собственное приложение; SaaS-части | Локальная SQLite, без входа | Wealthfolio |
| Контракт расширения | Нет | SDK аддонов с гайдами миграции. Он тоже меняется: 3.5 → 3.6 (песочница), 3.6 → 3.7 (ресурсы) | Wealthfolio |
| Долгосрочный риск | Весь проект на нас, включая обновления безопасности | Upstream может сменить направление или лицензию (CLA это позволяет); код, уже вышедший под AGPL, остаётся доступным | Wealthfolio |

## Цена форка — это место, где лежит наш код

Сколько upstream Wealthfolio меняет в местах, которые мы стали бы править:

| Что правим | Коммитов за 6 месяцев | Строк изменено за релиз: 3.6.3 → 3.7.0 / 3.7.0 → 3.8.0 | Нужно для |
|---|---|---|---|
| Главный дашборд (`pages/dashboard`) | 59 | 355 / 70 | Тонкий форк: место для виджета |
| Роутинг (`routes.tsx`) | 18 | 0 / 0 | Тонкий форк или своя папка |
| Навигация (`pages/layouts/navigation`) | 20 | 9 / 0 | Тонкий форк: пункт меню |
| Конфиг Tauri (`tauri.conf.json`) | 28 | 10 / 2 | Тонкий форк: автообновление, `identifier` |
| SDK аддонов (`packages/addon-sdk/src`) | 92 | 52 / 289 | Аддон |
| Внутренние типы и адаптеры фронтенда (`lib/types.ts`, `adapters/`) | 121 и 143 | 240 / 415 | Своя папка внутри форка |
| Интерфейс целей и планировщика (`features/goals`) | 66 | 822 / 1 249 | Глубокий форк планировщика |
| Ядро планировщика (`crates/core/src/planning`) | 20 | 0 / 1 252 | Глубокий форк планировщика |
| Операции (`crates/core/src/activities`) | 151 | 242 / 6 076 | Traspaso в ядре |

Места для тонкого форка меняются на десятки–сотни строк за релиз: конфликты редкие и мелкие. Места для
глубокого форка меняются на тысячи строк: конфликт почти в каждом релизе. Внутренние типы и адаптеры
в основном дополняются, а не переписываются, поэтому своя папка внутри форка ломается реже, чем глубокий
форк, но чаще, чем аддон.

## Формы форка

| Вариант | Где наш код | Цена обновлений | Свобода | Итог |
|---|---|---|---|---|
| ignidash, глубокий форк | Везде в ядре | Обновлений нет — нет и цены; всё сопровождение наше | Полная | Только если нужен веб-планировщик без учёта портфеля |
| Wealthfolio, тонкий форк + аддон (текущий план) | Аддон; в форке — несколько правок | Низкая: правки в местах, которые меняются на десятки–сотни строк за релиз; аддон — по гайдам миграции SDK | Ограничена песочницей аддона | **Рекомендую** |
| Wealthfolio, своя папка внутри форка | `features/es-planner/` плюс регистрация маршрутов и меню | Средняя: код опирается на внутренние типы и адаптеры | Без песочницы: Web Workers, любые данные и экраны | Запасной вариант, если песочница не потянет |
| Wealthfolio, глубокий форк встроенного планировщика | Ядро и интерфейс планировщика | Высокая: тысячи строк изменений за релиз в тех же файлах, плюс порт налогов на Rust | Полная | Не рекомендую |

## Когда пересмотреть выбор

- **Фаза 0 покажет, что песочница не тянет планировщик** (скорость, данные, интерфейс) — переносим его в свою
  папку внутри форка Wealthfolio, а не на ignidash: половина «учёт» в Wealthfolio уже готова.
- **Rust-сборка на вашем Windows не заводится** — аддон работает в официальной сборке, правки форка ждут.
- **Понадобится только веб-планировщик без учёта портфеля** и вы готовы вести 73 тыс. строк сами — тогда
  ignidash.

## Как держать форк дешёвым

- После каждого обновления на новый релиз записывать, сколько файлов upstream изменено в форке, сколько было конфликтов
  и сколько времени это заняло. Рост любой из цифр — сигнал выносить правки в аддон или в upstream.
- Для каждой новой правки форка сначала спрашивать: можно ли сделать это аддоном? Если нет — можно ли
  предложить в upstream?
- Остальные правила — в разделе «Свой форк Wealthfolio» в [wealthfolio-plan.md](wealthfolio-plan.md):
  без своих миграций БД, поверх релизных тегов, одна правка — один коммит.
