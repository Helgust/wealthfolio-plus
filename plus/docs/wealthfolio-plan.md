# Wealthfolio как основа: оценка и план

Дата: 2026-09-24. Изучен `github.com/wealthfolio/wealthfolio`, ветка `main`, коммит `5ef41f1` (23.09.2026).
Контекст: вы решили не писать планировщик с нуля, а дорабатывать существующий проект. Первый кандидат —
ignidash ([ignidash-fork-plan.md](ignidash-fork-plan.md)), второй — Wealthfolio. Какой из них выгоднее
дорабатывать в форке — [fork-comparison.md](fork-comparison.md).

Решения (24.09.2026):

- основа — Wealthfolio, испанский планировщик — его аддон;
- то, что аддону недоступно, делаем в своём тонком форке Wealthfolio;
- стек — TypeScript;
- репозиторий — форк `github.com/Helgust/wealthfolio_plus`, всё наше лежит в его папке `plus/`
  (раздел «Репозиторий и рабочий процесс»).

Открытые вопросы — в конце.

## Коротко

Основа — Wealthfolio, испанский планировщик — его **аддон**. Всё, что аддону недоступно, делаем
в **своём форке**; форк остаётся тонким.

1. **Проект живой.** Около 400 коммитов в месяц с февраля 2026 года, релизы каждые 1–4 недели
   (v3.8.0 — 07.09.2026), 9 тыс. звёзд. У ignidash развитие остановилось в марте 2026.
2. **Расширение — штатный путь.** У Wealthfolio есть SDK для аддонов с документацией, шаблоном и каталогом.
   Аддон получает свои страницы в боковом меню, доступ к данным и собственное хранилище. Поэтому в форк
   попадают только правки самого приложения, и его легко обновлять вслед за официальными релизами.
3. **«Текущие финансы» и Progress уже есть.** Счета и позиции с лотами FIFO (ровно то, что нужно для
   испанской базы сбережений), недвижимость и долги, история стоимости и взносов по дням. Шаг 7 нашей
   дорожной карты (импорт из Wealthfolio) и Progress закрываются сами. Шаг 7 предполагал, что позиции
   ведутся в Wealthfolio; на этом компьютере он пока не установлен — см. вопросы в конце.
4. **Приватность из коробки.** Десктопное приложение (Windows поддерживается), данные в локальной SQLite.
   Вычищать SaaS-части, как в ignidash, не придётся.

Чего Wealthfolio не даёт:

- **Встроенный планировщик для нас слишком прост.** FIRE/пенсионный планировщик с Monte Carlo там есть,
  но налог в нём — плоская ставка по трём корзинам (taxable / tax-deferred / tax-free). Нет прогрессивной
  шкалы, двух баз, половин estatal/autonómica, autónomo. Переписывать его не будем: планирование целиком
  живёт в аддоне.
- **Движок проекций и налоги пишем в аддоне на TypeScript.** Налоговое ядро переносим с Python — так же,
  как было бы с ignidash. Движок собираем из готовых частей: генераторы доходностей для Monte Carlo,
  бэктест, долги и недвижимость берём из ignidash (обе лицензии — AGPL-3.0, они совместимы). Структура —
  по нашей [architecture.md](architecture.md).
- **Песочница аддона ограничена.** Нет Web Workers и localStorage; запросы к localhost и частной сети
  заблокированы. Поэтому Python-ядро не подключить как локальный сервис: только TypeScript или Wasm.

## Wealthfolio: факты

| | |
|---|---|
| Что это | Локальный трекер личных финансов: инвестиции по счетам, net worth, доходность, цели, траты; FIRE/пенсионный планировщик; AI-ассистент (локальные LLM или свой ключ) |
| Стек | Tauri 2 (десктоп Windows/macOS/Linux, iOS) и веб-режим (Axum + Docker); ядро на Rust, SQLite; фронтенд — React 19, Vite, Tailwind 4, TanStack Query, Recharts 3, i18next |
| Лицензия | AGPL-3.0. Для вклада в upstream — CLA в пользу Teymz Inc. с правом перелицензирования, в том числе в проприетарную лицензию. Форки обязаны сменить имя и логотип (`TRADEMARKS.md`) |
| Объём | Rust ~308 тыс. строк (`crates/core` — 176 тыс.), фронтенд ~269 тыс. строк TS/TSX, 319 файлов тестов фронтенда |
| Активность | С 27.05.2024, 4 234 коммита; основной автор плюс сообщество. 9 039 звёзд, 720 форков, 472 открытых issues и PR |
| Языки интерфейса | de, en, es, fr, it, ja, ko, pt, zh, zh-Hant — русского нет |

Модель данных — что важно для нас:

- Типы счетов: `SECURITIES`, `CASH`, `CREDIT_CARD`, `CRYPTOCURRENCY`. Налоговых типов счетов нет.
- Позиции считаются из операций. Стоимость приобретения — только FIFO; лоты (дата, количество,
  стоимость, цена, комиссии) доступны аддонам.
- Альтернативные активы: недвижимость, транспорт, коллекции, металлы, долги — с ценой и датой покупки.
- История по дням: стоимость, стоимость приобретения, чистые взносы, внешние потоки — в базовой валюте.
- Мультивалютность с курсами.
- Отдельной операции traspaso нет: `TRANSFER_OUT` снимает лоты по FIFO, `TRANSFER_IN` задаёт стоимость
  приобретения. Подходит ли это для traspaso — проверить в фазе 0.

Встроенный планировщик (`crates/core/src/planning/retirement`, `features/goals/retirement-planner`):

- режимы FIRE и «traditional»; расходы по статьям (начало и конец по возрасту, essential), пенсии DB/DC,
  glide path, взносы с ростом;
- Monte Carlo на Rust (по умолчанию 100 000 прогонов), стресс-тесты, сценарии, риск последовательности
  доходностей, матрицы чувствительности;
- налог — плоская ставка при изъятии по корзинам и штраф за раннее изъятие; корзина назначается каждому
  счёту в настройках цели. Поле `countryCode` в модели есть, но в расчёте не используется.

Аддоны:

- Модуль на TypeScript/React в изолированном iframe (`sandbox="allow-scripts"`). Хост предоставляет
  React 19.2, TanStack Query, `@wealthfolio/ui`, Recharts 3.7, date-fns, lucide-react.
- API: счета; позиции и лоты; история стоимости; доходы (дивиденды, проценты); операции; котировки; курсы;
  альтернативные активы; цели; настройки; `storage` (ключ → строка); `secrets`; события; навигация.
- Нельзя: localStorage, Web Workers, прямые сетевые запросы, обращения к localhost и частной сети через
  `network`. Можно: Wasm из пакета аддона.
- Права объявляются в `manifest.json` и проверяются статическим анализом кода при установке.
- Распространение — ZIP-файл или каталог. Горячая перезагрузка требует запустить Wealthfolio из исходников
  в режиме разработки аддонов (Rust + Tauri); без неё — сборка ZIP и переустановка.
- API аддонов меняется между минорными версиями: есть гайды миграции 3.5 → 3.6 → 3.7.

## Как дорабатываем Wealthfolio

Три уровня — от простого к сложному:

1. **Аддон — основное.** Весь планировщик: модель, налоги, движок, экраны. Аддон работает и в официальной
   сборке Wealthfolio.
2. **Свой форк — там, где аддон не может.** Только правки самого приложения: места для виджетов, перевод,
   операции ядра, недостающие API. Подробно — в разделе «Свой форк Wealthfolio».
3. **Upstream — куда получится.** Общие правки из форка предлагаем мейнтейнерам (нужна подпись CLA).
   Принятое удаляем из форка, и он становится тоньше.

Встроенный Rust-планировщик под испанские налоги не переписываем: планирование целиком живёт в аддоне,
дублировать его в ядре незачем.

## Опыт ProjectionLab в Wealthfolio

Почти весь опыт ProjectionLab — это экраны плана, а их мы делаем в аддоне сами. Остальное Wealthfolio
уже умеет. Роли делятся так:

- **Wealthfolio — «что есть»:** счета, позиции, недвижимость, долги, история net worth. Это Current Finances
  и фактическая часть Progress. Счёт можно вести операциями или просто снимками остатков (режим
  `HOLDINGS`) — как ручной ввод в ProjectionLab.
- **Аддон — «что будет»:** планы, их сравнение, налоги, Monte Carlo.

Концепции ProjectionLab из [architecture.md](architecture.md) §1:

| ProjectionLab | Где в Wealthfolio + аддон |
|---|---|
| Current Finances | Wealthfolio: счета, позиции, альтернативные активы, долги. В аддоне — сопоставление счетов с испанскими типами и сводка по ним |
| Plans | Аддон: несколько планов; каждый стартует с текущих данных Wealthfolio |
| Accounts, Real assets, Debts | Стартовые значения — из Wealthfolio, проекция — в аддоне |
| Income, Expenses, Milestones | Аддон: карточки событий с началом и концом по году, возрасту или milestone |
| Cash-flow priorities, Withdrawal strategy | Аддон: упорядочиваемые списки |
| Tax analytics | Аддон: IRPF estatal/autonómica, база сбережений, RETA, IBI; эффективная и предельная ставки |
| Monte Carlo, Historical backtesting, Chance of success | Аддон: success rate, веер перцентилей, просмотр отдельного прогона |
| Cash-flow Sankey | Аддон: компонент `Sankey` из Recharts — Recharts предоставляет хост |
| Today's dollars | Аддон: переключатель «номинал / евро сегодня» на всех графиках |
| Compare plans | Аддон: наложение кривых и таблица разницы ключевых метрик |
| Progress | Факт — история net worth в Wealthfolio; план против факта — в аддоне |

Как это будет выглядеть:

- В боковом меню Wealthfolio появляются разделы аддона: **Планы**, **Сравнение**, **Прогресс**.
- Страница плана: сверху график net worth по годам с разбивкой по типам счетов, отметками milestones
  и ключевыми метриками. Под ним вкладки **План · Денежный поток · Налоги · Monte Carlo · Таблица**.
  «Таблица» — ledger по годам в редактируемой `data-grid` из `@wealthfolio/ui` с экспортом в CSV.
- Клик по году на графике открывает боковую панель с разбивкой года: доходы, налоги, flows, балансы.
- Редактирование — в выезжающих панелях. Формы на `@wealthfolio/ui` + react-hook-form + Zod, как в самом
  Wealthfolio, поэтому аддон выглядит родным: та же тема, светлая и тёмная.
- Детерминированный прогон годового движка должен занимать миллисекунды, так что план перестраивается при
  каждом изменении. Monte Carlo — по кнопке. Время проверяем в фазе 0.

Чего аддон не может — это делаем в форке:

- **Встроиться в экраны самого Wealthfolio.** Аддон размещает ссылки только в боковом меню; остальные места
  в манифесте зарезервированы на будущее. В форке добавляем место на главном дашборде: там виджет аддона
  покажет прогноз плана рядом с фактическим net worth.
- **Изменить встроенный планировщик** (Goals → Retirement). В форке этот пункт меню ведёт на наш
  планировщик.
- **Перевести сам Wealthfolio на русский.** Если интерфейс будет русским, перевод Wealthfolio делаем
  в форке.

## Свой форк Wealthfolio

Форк — тонкий слой правок поверх официальных релизов. Логики планировщика в нём нет: расчёты и экраны
живут в аддоне, поэтому аддон работает и в официальной сборке.

Что идёт в форк:

| Правка | Почему не аддоном | Когда | В upstream |
|---|---|---|---|
| Место на главном дашборде для виджета аддона — прогноз плана рядом с фактическим net worth | Аддон ставит ссылки только в боковое меню | Фаза 4 | Предложить: в манифесте уже зарезервированы другие места |
| ~~Русская локаль Wealthfolio~~ | Не нужна: интерфейс английский (решение 25.09.2026) | — | — |
| `portfolio.getNetWorth` в API аддонов — стартовый net worth как на странице Net Worth | Набор API задаёт приложение | Фаза 1 (сделано) | Предложить |
| Пункт Goals → Retirement ведёт на наш планировщик | Встроенные экраны аддоном не изменить | Фаза 3 | Нет, это личная настройка |
| Операция traspaso: фонд → фонд с переносом стоимости и дат приобретения | Позиции и лоты считает Rust-ядро | Фаза 2, если в фазе 0 `TRANSFER_OUT` + `TRANSFER_IN` не подойдут | Возможно |
| Недостающие методы API аддонов | Набор API задаёт приложение | По итогам фазы 0 и дальше по мере нужды | Предложить |

Правила форка:

- **Минимум кода в форке.** Только места расширения и небольшие правки; всё, что можно, — в аддоне.
  Там, где аддон может обойтись без форка, он обходится: например, страницы аддона работают и без виджета
  на дашборде.
- **Никаких своих миграций БД.** Upstream добавляет миграции по датам (сейчас их 51). Своя миграция в той
  же базе ломает будущие обновления и возврат на официальную сборку. Если без изменения схемы никак —
  сначала предлагаем изменение в upstream.
- **Основа — релизы, а не `main`.** Ветка `plus` начинается с последнего тега (сейчас `v3.8.0`); новый
  релиз вливаем мержем его тега (почему не ребейз — в разделе «Репозиторий и рабочий процесс»). После
  мержа: `pnpm check`, тесты затронутых крейтов, `pnpm test:e2e:addon-sandbox`, сборка установщика.
- **Одна правка — один коммит** с пометкой, предложена ли она в upstream. Принятое в upstream из форка
  удаляем.

Сборка и установка:

- Репозиторий — `github.com/Helgust/wealthfolio_plus`, публичный GitHub-форк. Как он устроен — в разделе
  «Репозиторий и рабочий процесс».
- Инструменты — как в upstream: Node 24, pnpm 10.33 (standalone `pnpm.exe`, см. `next-steps.md`), Rust из
  `rust-toolchain.toml` (для `v3.8.0` — 1.95.0), Visual Studio Build Tools (C++), WebView2 (в Windows 11 уже есть). Установщик собирается командой `pnpm tauri build`.
- Сборка из исходников заодно даёт горячую перезагрузку аддона при разработке.
- Автообновление в форке выключаем (плагин `updater`, настройки в `apps/tauri/tauri.conf.json`), иначе
  официальное обновление встанет поверх форка.
- Данные. На этом компьютере Wealthfolio пока не установлен. Десктоп хранит данные в
  `%APPDATA%\<identifier>`; переменной вроде `WF_DATA_DIR` у него нет. В разработке форк запускается с
  оверлеем `plus/tauri.dev.conf.json` (`identifier` = `com.helgust.wealthfolio-plus.dev`), поэтому его
  данные лежат отдельно от официальной сборки. Если рядом появится официальное приложение, у форка должен
  быть свой `identifier`, иначе они будут делить одну базу. Когда форк станет основным, ставим его вместо
  официального с тем же `identifier` (`com.teymz.wealthfolio`). Форк собираем из тега не старше
  установленной официальной версии — база назад не откатывается. Перед переключением делаем резервную
  копию: экспорт SQLite есть в самом Wealthfolio.
- Лицензия и товарный знак для личной сборки ничего не требуют. Если когда-нибудь делиться сборкой —
  сменить имя и логотип (`TRADEMARKS.md`) и открыть исходники (AGPL). Не юридическая консультация.

## Репозиторий и рабочий процесс

Форк — `github.com/Helgust/wealthfolio_plus`. Рабочая папка — его клон, например
`E:\GameDeveloping\wealthfolio_plus`. Всё наше лежит в папке `plus/`: upstream её никогда не трогает,
поэтому при обновлениях она не конфликтует.

```
wealthfolio_plus/
├── apps/ crates/ packages/ …   Wealthfolio и наши точечные правки (одна правка — один коммит)
├── CLAUDE.md                    новый: подключает AGENTS.md и plus/CLAUDE.md
└── plus/
    ├── CLAUDE.md                правила нашей части: язык, налоги, источники
    ├── .prettierrc.cjs          настройки upstream, но без переноса строк в Markdown
    ├── docs/                    architecture, spain-tax-notes, этот план, сравнения
    ├── python/                  нынешний BetterFinancePlanner: planner.tax, rules/, tests/ — эталон
    └── addon/                   аддон Planificador ES (появится в фазе 0)
```

Ветки:

- `main` — зеркало upstream, в него не коммитим. Его можно вообще не трогать: обновления берём из remote
  `upstream`.
- `plus` — рабочая ветка от тега `v3.8.0`. От `main` не начинаем: там уже неопубликованные изменения 3.9
  и новые миграции базы. На GitHub делаем `plus` веткой по умолчанию.

Обновление до нового релиза Wealthfolio:

```
git fetch upstream --tags
git switch plus
git merge v3.9.0       # конфликты возможны только в наших правках файлов Wealthfolio
pnpm install
pnpm check             # затем тесты затронутых крейтов и сборка
git push
```

Мержим, а не ребейзим: в `plus` будут сотни наших коммитов (аддон, Python, документы), и ребейз
переписывал бы их на каждом релизе, а потом требовал force-push. Наши правки файлов Wealthfolio всегда
видны одной командой: `git diff v3.9.0 plus -- . ":(exclude)plus"`.

Аддон — отдельный пакет в `plus/addon/` со своим lock-файлом, вне pnpm-workspace Wealthfolio. Иначе его
зависимости попали бы в общий `pnpm-lock.yaml` и конфликтовали при каждом обновлении. SDK, UI и dev-tools
берём из npm той же версии, что база форка: сейчас это 3.8.0, она опубликована. Если понадобится API,
которого нет в официальном SDK (например, место на дашборде), подключаем `packages/addon-sdk` форка
через `link:`.

Разработка:

Правила:

- Форк публичный: всё закоммиченное видно всем. Личные данные — только в файлах из `.gitignore` и в папке

- Недвижимость и кредиты — из альтернативных активов Wealthfolio: IBI, imputación de rentas, exención por
  reinversión при продаже vivienda habitual, ITP при покупке новой.
- Пенсия Seguridad Social — входной доход; политика проекции правил `frozen | indexed`.
- Форк: пункт Goals → Retirement ведёт на планировщик аддона.

**Условие перехода:**

- [x] два плана сравниваются на одной странице (на стенде; в форке — за пользователем);
- [x] milestone по условию срабатывает в тесте движка;
- [x] Sankey любого года сходится: доходы = налоги + траты + взносы + изменение остатков;
- [ ] продажа vivienda habitual с реинвестицией не даёт прироста в базе сбережений.

#### Срезы фазы 3

Каждый срез вертикальный: модель → движок → страница → тесты; закрывается зелёными `vitest`, `tsc`,
`pytest`, `ruff`. Порядок — сверху вниз; срезы 3 и 4 можно менять местами.

1. **Несколько планов и сравнение** (трассирующий срез).
   - Хранение: индекс `plans.v1` (`ids`, `activeId`), план — под `plan.v1:<id>`. Единственный план
     фаз 1–2 (`plan.v1`) при первом запуске становится первым планом; старый ключ не удаляется.
   - Страница плана: выбор плана, New, Duplicate, Delete (с подтверждением).
   - Страница Compare — вторая ссылка в боковом меню: кривые net worth выбранных планов на одном
     графике, таблица метрик с разницей к первому плану. Стартовая точка у всех планов общая —
     текущие данные Wealthfolio.
   - Тесты: перенос `plan.v1`, метрики сравнения. Гейт — условие 1.
2. **Milestones и события.**
   - `Milestone`: год, возраст человека или условие «net worth ≥ X» (X в евро первого года).
     Условие проверяется по net worth на конец прошлого года и срабатывает один раз.
   - `Timing` = год | возраст | milestone | нет — начало и конец расходов, конец дохода autónomo,
     начало пенсии. План фазы 2 читается без миграции: число в `startYear`/`endYear` → «год»,
     `untilAge` → «возраст».
   - Пенсия Seguridad Social — доход человека: сумма в год в евро первого года, начало (`Timing`),
     рост с инфляцией (revalorización по IPC); облагается как `trabajo_integro`.
   - Вкладка Plan: карточки доходов, расходов и milestones; flows и порядок изъятий переезжают сюда
     из Edit plan. Отметки milestones на графике; клик по году — панель с разбивкой года.
   - Тесты: milestone по условию срабатывает в тесте движка (гейт — условие 2); план фазы 2 читается.
3. **Денежный поток.**
   - Ledger получает все потоки года: доходы (autónomo, пенсии, проценты и дивиденды, выплаты
     планов, продажи) и расходы (gastos, RETA, IRPF, траты, взносы, вложения).
   - Вкладка Cash flow: Sankey выбранного года (`Sankey` из Recharts хоста).
   - Тест: для каждого года доходы = налоги + траты + взносы + изменение остатков (гейт — условие 3).
4. **Spending rules и проекция правил.**
   - Правило трат действует с выбранного milestone и меняет только discretionary; essential —
     неизменный пол (решение 25.09.2026). Правила: фиксированная сумма в евро первого года (как
     сейчас), % портфеля, Guyton–Klinger.
   - Правила после последнего известного года: `frozen` (как сейчас) или `indexed` по инфляции
     плана — порт `IrpfRules.indexed(factor)` в TS, сверка с Python на фикстуре.
5. **Недвижимость и кредиты.**
   - Сначала эталон: `rules/<год>/inmuebles.yaml` — imputación de rentas (art. 85 LIRPF), exención
     por reinversión (art. 38 LIRPF, art. 41 RIRPF), ITP Comunitat Valenciana — с источниками
     BOE/DOGV; функции в `planner.tax`, тесты, выгрузка в TS.
   - Недвижимость и долги — из `getAlternativeHoldings` (форк). Wealthfolio даёт стоимость, цену
     и дату покупки, у долга — исходную сумму, дату, ставку и связь с активом. Остальное задаётся
     в аддоне (`properties.v1`, общий для планов): vivienda habitual или нет, valor catastral,
     IBI € в год, доля владения; у кредита — ежемесячный платёж или срок.
   - События плана: продажа (прирост в базе сбережений, exención por reinversión), покупка (ITP),
     аннуитет кредита.
   - Тест: продажа vivienda habitual с реинвестицией не даёт прироста в базе сбережений
     (гейт — условие 4).
6. **Форк: Goals → Retirement** ведёт на планировщик аддона. Отдельный коммит `feat(fork/goals)`.

- **Срез 2 — код готов, проверен на стенде с выдуманными данными.** `Timing` (год | возраст
  человека | milestone), событие активно с года начала до года конца, не включая его;
  `engine/timing.ts`. Milestone по net worth срабатывает в году, который начинается с таким net
  worth в евро первого года, один раз. Планы фаз 1–2 читаются: `untilAge` → конец «возраст»,
  `endYear` (включительно) → конец `endYear + 1` — активные годы те же. Пенсия Seguridad Social —
  `trabajo_integro`, растёт с инфляцией. Вкладка Plan — карточки; Edit на карточке открывает свой
  раздел редактора, flows и порядок изъятий редактируются из карточки Cash-flow priorities.
  Отметки milestones на графике, клик по году — панель года. Шаблон нового плана получил
  milestone Retirement (65) и пенсию SS с 67. Исправлена легенда графика net worth: хост красил
  квадратики цветом обводки областей, то есть фоном.
- **Срез 3 — код готов, проверен на стенде.** Ledger получил вложения и изъятия по типам счетов,
  дефицит и рыночный рост (`deposits`, `withdrawals`, `shortfall`, `marketGrowth`). Вкладка Cash
  flow: Sankey выбранного года через узел «Cash flow» и те же числа таблицей (`lib/cashflow.ts`,
  `components/cashflow-tab.tsx`). Тест на каждом годе трёх сценариев (жизнь целиком, продажа
  с убытком, кончились деньги): источники = использование, и изменение net worth = вложения −
  изъятия − дефицит + рост. Тест нашёл утечку: при продаже с убытком IRPF падал, продано было
  больше нужного, и излишек пропадал из модели — теперь он остаётся в cash.
- **Срез 4 — код готов, проверен на стенде.** Правила после последнего известного года:
  `taxRules: frozen | indexed`; `indexRules` — порт `IrpfRules.indexed`, сверен с Python на
  фикстуре `rules_indexed` (2 года × 3 множителя). Правило трат (`spending`): с момента начала
  правило задаёт, сколько дают счета за год (% портфеля на начало года или Guyton–Klinger:
  старт rate × портфель, рост с инфляцией, −adjustment выше rate × (1 + guardrail), +adjustment
  ниже rate × (1 − guardrail)); discretionary = доходы + эта сумма − расходы − essential − налоги
  с учётом налога на саму продажу, не меньше 0; запланированные discretionary при этом не
  действуют. Упрощения Guyton–Klinger: нет правила «не индексировать после убыточного года» и
  исключения последних 15 лет. Пока правило действует, профицит не откладывается — он тратится.
